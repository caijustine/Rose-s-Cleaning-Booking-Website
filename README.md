# Rose's Cleaning & Janitorial — Business Website

A static business website for **Rose's Cleaning & Janitorial**, a licensed and insured family cleaning service based in St. George, Utah. A multi-page static site generated by a small, dependency-free Node script (`src/build.mjs`) — plain HTML, CSS, and vanilla JavaScript, no frameworks.

## Live Site

**https://roses-cleaning.com**

## Hosting & Deployment

The site is hosted on **[Railway](https://railway.com)** (project `reliable-eagerness`, service `Rose-s-Cleaning-Booking-Website`, environment `production`), with **Cloudflare** in front of the custom domain.

- **How it runs** — Railway runs `npm start`, which uses [`serve`](https://www.npmjs.com/package/serve) to serve the generated `public/` folder on `$PORT`. `public/` is committed to git, so Railway doesn't need to build anything. `public/serve.json` sets clean URLs, trailing slashes, caching, and security headers.
- **Auto-deploy** — Railway is connected to this GitHub repo. Every push to `main` triggers a new deploy, which is usually live within about a minute.
- **Domains**
  - `roses-cleaning.com` — primary custom domain (proxied through Cloudflare)
  - `rose-s-cleaning-booking-website-production.up.railway.app` — Railway's default domain
  - `www.roses-cleaning.com` — not configured yet (doesn't resolve)
- **Cloudflare email obfuscation** — Cloudflare rewrites `mailto:` links on the live site to protect them from scrapers, so the served HTML won't match `public/` byte-for-byte. This is expected.
- **Railway CLI** — `railway link` (select the project above), then `railway status`, `railway logs`, or `railway deployment list` to inspect deploys.

> GitHub Pages is **not** used for this site. Pages is disabled on the repo.

## SEO built in

- Unique title, meta description, and canonical URL on every page
- Open Graph / Twitter share previews (`src/assets/img/og-image.jpg`)
- JSON-LD structured data: `HouseCleaning` business on every page, plus `Service`, `BreadcrumbList`, and `FAQPage` where relevant
- Auto-generated `sitemap.xml` and `robots.txt`
- One `<h1>` per page, descriptive alt text, internal links between services and areas
- Fast loading: responsive WebP images, self-hosted fonts, deferred scripts, long-lived caching for assets

## Running Locally

```bash
npm install
npm run dev      # builds, then serves at http://localhost:3000
```

`npm run build` regenerates `public/` without starting a server. The dev server doesn't auto-reload, so after editing `src/`, run `npm run dev` again and refresh the browser.

## Making Changes

- **Text, prices, services, areas, reviews, FAQs, phone, email, hours** — edit `src/data.mjs`
- **Page layout / sections** — edit the templates in `src/build.mjs`
- **Styling** — edit `src/assets/css/site.css`
- **Photos** — add originals to `images/`, run `./scripts/optimize-images.sh` (needs `brew install webp`), then reference them in `src/data.mjs`
- **Add a service area** — add an entry to `areas` in `src/data.mjs` with its own local copy (avoid copy-pasted city pages; Google treats them as spam)

Then run `npm run build` and **commit the updated `public/` folder along with your `src/` changes**. Push to `main` and Railway deploys it to roses-cleaning.com.
